## Per-order quantity limit

Inventory has persistent `maxPerOrder`, initially 2147483647. Inventory reads
and inventory-command responses include this positive signed 32-bit integer.

| Request | Success | Failure |
|---|---|---|
| PUT /inventory/{sku}/quantity-limit with `{maxPerOrder}` | 200 inventory view; changes only the limit | 400 invalid body/value; otherwise 404 unknown SKU |

The body must be an object with a required, non-null `maxPerOrder` JSON number
whose value is an integer from 1 through 2147483647. Numeric strings, booleans,
fractional values and out-of-range numbers are rejected. Integral forms such as
`1.0` and `1e0` have the same meaning as `1`. Property names are case-sensitive;
extra properties are ignored and cannot select identity or authorization.
Malformed/missing bodies and invalid values return 400 **before** SKU lookup,
including for an unknown SKU. Error prose/body for 400/404 is unspecified.
Repeated valid updates succeed. Failed updates write nothing.

For new fulfillment, insert `QuantityLimitExceeded` when quantity exceeds the
limit, after `InvalidQuantity` and before `InsufficientStock`. Return
`{status:"Rejected",outcome:"QuantityLimitExceeded"}` with HTTP 200 at completion.
Direct submission does not use inventory limits. Completed-request replay and
existing-reservation precedence are unchanged. Domain rejection leaves no new
reservation or net stock change; compensation, when used, is exempt from the
limit. Limits on unrelated SKUs remain unchanged.
