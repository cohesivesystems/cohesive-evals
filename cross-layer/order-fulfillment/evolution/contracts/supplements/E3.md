## Inventory quarantine

Inventory has persistent Boolean `quarantined`, initially false. Inventory reads
and inventory-command responses include it alongside existing inventory fields.

| Request | Success | Failure |
|---|---|---|
| POST /inventory/{sku}/quarantine | 200 inventory view, quarantined=true | 404 unknown SKU |
| POST /inventory/{sku}/clear-quarantine | 200 inventory view, quarantined=false | 404 unknown SKU |

Both commands are idempotent. No request body is required or read; an optional
body is ignored. Only `quarantined` changes: available stock, quantity limits and
other SKUs are preserved. Authorization is the existing host-provided identity.

For new fulfillment, insert `InventoryQuarantined` after `InvalidQuantity` and
before `QuantityLimitExceeded`, stock shortage and lifecycle restrictions.
Return HTTP 200 `{status:"Rejected",outcome:"InventoryQuarantined"}` at completion.
Completed-request replay and existing-reservation precedence are unchanged.
Direct submission is unaffected. Completed rejection has no new reservation or
net stock change; compensation, when used, remains allowed while quarantined.
