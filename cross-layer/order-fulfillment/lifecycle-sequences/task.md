# Offline order lifecycle sequence pilot

Start every sequence from a fresh Submitted order "order-A" (partition "partition-A" where applicable), unheld, with three remaining units. Carry the actual returned order forward after each command. Pack accepts in Submitted or Packed, resulting in Packed. Unpack accepts in Packed or Submitted, resulting in Submitted. Hold and Release accept only in Packed, including repeats, and set the hold flag true and false respectively. Packing and unpacking preserve the hold. Ship(q) accepts only in Packed, unheld, with 1 <= q <= remaining. Subtract q and stay Packed unless zero remains, then become Shipped. Shipped rejects every command. Rejections preserve the entire state. Preserve identity on every step.

Write only Suite/Submission.cs. Implement static class Submission with public static string[][] Propose() and public static IEnumerable<Seen> Execute(string[] commands). Seen is a supplied record (bool Accepted, string Status, string Id, bool Hold, int Remaining). Commands are Pack, Unpack, Hold, Release, and Ship:-1 through Ship:4. Return one observation after each command. Execute arbitrary legal command lists using the actual production domain API (Order.Apply or typed OfflineTransition.Prepare/Execute); never fabricate observations or consult expectations. The independent grader owns the oracle.

Budget per fresh author: eight minutes from dispatch, at most four distinct sequences of one to eight commands each, one condition only. Include Pack, Ship:1, Hold, Ship:2, Release, Ship:2 as one continuous sequence (extra commands are allowed). Inspect only this fixture, its application and task. No other suites, panels, repository history, or external assistance. Rehearse with dotnet build Suite/Suite.csproj --no-restore and dotnet run --project Suite --no-build. Stop when satisfied. No edits after freeze.
