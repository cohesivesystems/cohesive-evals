# Frozen pick-list protocol

Issue #76 and G0 source d65d439f07205c14753ead83a02e6c6a072480d9 define both arms. The 100,000 and 1,000,000 totals include six controls. Remaining history has IDs H plus seven decimal digits starting at 0000001, location L00, priority zero, shipped, no reservations. Physical stock is separate from the original unreserved inventory counter. Each reservation has a distinct line ID. Acceptance uses the canonical page hashes in golden.json, frozen before implementation.

Start one fresh database and one application per repetition. Verify controls and restart after a committed hold while the app is down; restore baseline before warm-up. Warm foreground reads for 60 seconds. Then issue 19,200 foreground reads over 600 seconds independently of 6,000 mutations. Poll the changed location on commit acknowledgment then every 100 ms until visible or superseded. Count missed visibility as infinite. Accept only a committed page during a request (including an earlier committed page during async convergence). Check all locations immediately after the last commit. Include all app and database work during measurement; snapshot PostgreSQL database block hits/reads, container CPU counters and resident memory, capture plans separately. Use issue #76 limits and deadlines. Alternate arm order across paired runs; do not change the candidate after seeing measured results. Setup failures are separate from failed observations.
